# Phase 5 web application

React + Vite + TypeScript with Vietnamese UI, native session cookies and Recharts.
No external fonts, analytics, trackers, bank links, OCR or additional MVP features.
Pages use hash navigation so the static production build needs no route rewrite.
The local Vite proxy sends /api to the existing Express server.

## Run against local PostgreSQL 18

Use pinned Node 22.23.4/npm 10.9.4, then:

```sh
npm ci
npm run db:migrate
# Terminal 1; uses the ignored local .env, explicitly fake to avoid Gemini calls:
LLM_PROVIDER=fake npm run api:start
# Terminal 2:
npm run web:dev
```

Open http://localhost:5173, register a synthetic account and use sample data only.
APP_ORIGIN must be http://localhost:5173 for local browser requests. Use localhost
consistently; cookies are host-scoped. The API listens on 127.0.0.1:3000. A local
PostgreSQL installation is sufficient for development; Docker is used only for
isolated tests here. Deployment/container packaging remains a later phase.

```sh
npm run web:build
npm run web:preview
```

Preview also proxies /api locally. The production bundle is apps/web/dist. This
Vite preview is a local QA server, not the eventual public deployment architecture.
No API key, database URL or session secret belongs in VITE_* variables or client code.

## Behavior

- Register/login/logout; profile restoration on reload. Cookie authentication and
  in-memory CSRF only; no token, message or ledger storage in localStorage.
- Chat: max 500 characters, editable confirmation cards, unresolved amount/date
  fields required, visible clarification and uncertain-card highlighting. No parse
  action inserts a ledger row. Confirm validates again on the API.
- A confirmation attempt snapshots its items and UUID key. A lost response keeps
  that snapshot locked; retry reuses it. Definite validation rejection lets the user
  edit again. Pending intent is memory-only: avoid reloading/leaving while a save is
  uncertain; inspect Transactions before entering it again after a reload. There is
  no background queue or offline synchronization.
- Transactions: from/to/type/category filters, forward/back cursor pages, edit and
  explicit delete confirmation. Goals support create/edit/delete and contributions.
- Reports: month/year, exact totals, category/day/month/top-note tables. Recharts
  distinguishes series by labels and line/marker shape, with keyboard support and
  expanded HTML table alternatives. Chart coordinates are approximate thousands;
  tables and money labels use exact bigint values and Intl.NumberFormat vi-VN.
- Budgets show textual 80/100% status with a progress indicator, not color alone.
  Goal daily amounts/progress come from the API's integer calculations.
- Settings: transaction CSV download, logout (also reachable on mobile), brief
  privacy explanation and account deletion requiring the typed word XÓA.
- Visible synthetic-demo banner, loading/empty/error/retry states, native labeled
  controls, skip link, focus movement on navigation and mobile bottom navigation.
  No chart, toast or financial calculation is generated by an LLM.

## Browser tests

Docker must run. Stop local servers on ports 3000/5173 first; the harness deliberately
refuses server reuse. It never reads .env, touches the local development database or
calls Gemini. Each run creates disposable PostgreSQL 18 with FakeProvider, starts
the production web build and cleans up its own servers/container.

```sh
npx playwright install chromium
npm run e2e
# One project or test while debugging:
npm run e2e -- --project=desktop-chromium --grep 'retry after'
```

Seven journeys run on desktop Chromium and Pixel 7 Chromium emulation. They cover the
full required flow, ambiguous input, a response lost after successful persistence,
transaction changes, budget thresholds, reload/logout/keyboard skip navigation,
report error/retry, yearly table, cursor filters and goal edits/deletion. Browser error assertions are included in the
full smoke. Screenshots use synthetic data only and are in docs/screenshots.
The owner approved the retained Chat/Dashboard screenshots for README on 2026-11-03.

Playwright gathers V8 execution ranges and merges them across journeys. The retained
web-coverage.json measures UTF-16 ranges in all built JS including React/Recharts;
it is not TypeScript line/branch coverage and excludes HTML/CSS/API. No whole-app
coverage or manual accessibility certification is inferred from this measurement.

## Lighthouse measurement

```sh
npm run web:build
# Terminal 1, isolated data and FakeProvider:
npm run e2e:serve
# Terminal 2:
npm run web:audit
```

The script creates a temporary synthetic account, seeds two transactions, audits
Chat and Dashboard using Lighthouse mobile simulated throttling, then deletes its
account and closes Chrome. Stop the preview with Ctrl+C afterward. The script uses
local ports 3000/5173 and Chrome debugging port 9222. Do not point it at a real user
session or deploy it publicly. It retains selected metrics only; full Lighthouse
reports may include cookies and are deliberately not written.

See docs/measurements/lighthouse.json and EVIDENCE.md for measured scores and exact
conditions. Each result is one local run, not a percentile, hosted latency promise,
WCAG certificate, real-phone test or a measured Gemini response time. Tests/CI use
Chromium; Safari/Firefox and assistive-technology testing remain unverified.
